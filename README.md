# KeyNoise Guard (キーボード打鍵騒音 リアルタイム検知システム)

KeyNoise Guardは、キーボードの打鍵音（特にタイピング時の「強打」や騒音）をマイク入力からリアルタイムに検知・可視化し、快適なタイピング環境と周囲への配慮をサポートするWebアプリケーションです。

ブラウザとマイクだけで動作し、サーバーへの音声データ送信は一切行わないため、セキュリティやプライバシー面でも安全に利用できます。

## 🚀 使い方 (画面+主要操作3ステップ)

ブラウザ上で以下の3ステップを実行するだけで、即座にタイピング騒音の監視を開始できます。

1. **マイク監視の開始**
   - 画面上の「**監視開始**」ボタンをクリックし、ブラウザのマイク使用許可を与えます。
2. **ノイズ環境の測定（キャリブレーション）**
   - 部屋を静かにした状態で「**静寂測定（3秒）**」をクリックします。現在の部屋の環境騒音（エアコン等の雑音）のベースラインが測定され、検知しきい値が自動調整されます。
3. **感度調整と誤検知フィルターの選択**
   - キーを叩いてみて、しきい値ゲージを越えて「強打検知」するか試します。
   - 反応しづらい場合は「**マイク入力ゲイン**」スライダーを上げて調整します。
   - 話し声等で誤検知する場合は、「**キー連動モード**」（キーを押した直後だけマイクをONにする機能）や「**ノイズゲート**」をONにして誤判定をカットします。

## 🌟 主な機能と特徴（詳細）

### 1. リアルタイム音声解析と波形表示
- **Web Audio API**を使用した高速な音声解析。
- キャンバス上にリアルタイムで音声波形と検知レベル（シグナル比率）を描画。

### 2. 高精度な打鍵音検知ロジック（ノイズ除去）
- **ハイパスフィルタ (600Hz):** 人の声の基本周波数や空調などの低周波ノイズをカットし、打鍵音の鋭い高周波成分を強調します。
- **急上昇率ゲート (Rise-rate gate):** 音量が緩やかに上がる話し声と異なり、1フレームで急峻に立ち上がる打鍵音のトランジェント（過渡特性）を判定して誤検知を防ぎます。
- **持続信号拒否 (Sustained-signal rejection):** 一定以上の音量が持続する信号（話し声や空調音など）を検知対象から自動で除外します。

### 3. 多彩なキャリブレーションモード
- **静寂キャリブレーション:** 周囲の静かな時のノイズフロア（基準値）を測定し、個々の環境に合わせた最適なしきい値を設定します。
- **打鍵音パターン学習 (スペクトル指紋):** 実際にキーを数回入力し、その周波数特性を「指紋（フィンガープリント）」として学習。コサイン類似度を用いて、打鍵音に類似した音だけを検知します。
- **動的ノイズ追従モード:** 周囲の環境騒音の変動に合わせて、リアルタイムでノイズフロアを自動追従・調整します。

### 4. 便利なユーザーインターフェース
- **keydown 連携モード (キー連動ゲーティング):** Webページ上で物理的にキーが入力された直後（350ms間）だけ音声解析を有効にすることで、周囲の雑音による誤検知を極限まで減らします。
- **Picture-in-Picture (PiP) 表示:** 解析画面やレベルメーターを小さなフローティング窓（PiP）として画面隅に常時表示可能。作業中のゲームやテキストエディタの裏で動作させながら監視できます。
- **ダーク/ライト テーマ切替:** 使用環境に合わせて目に優しいデザインへ変更できます（選択したテーマはブラウザに記憶され、次回起動時も適用されます）。
- **アラート機能:** 許容値を超えた強打を検知すると、画面が赤くフラッシュ・振動し、オプションで警告音（ブラウザ合成音）を鳴らせます。
- **ログ記録とCSV出力:** 検知した時間や強度のログをリアルタイムでリスト化。CSVファイルとしてエクスポート可能です。

## 🛠️ 使用技術・AI活用

### 1. 使用技術
- **フロントエンド:** HTML5 / CSS3（バニラCSS / 変数によるライト・ダークテーマ切替設計）
- **音声処理・API:** Web Audio API（`BiquadFilterNode` の600Hzハイパスフィルター, `AnalyserNode` による波形取得, `OscillatorNode` での合成音アラート）
- **ブラウザAPI:** Document Picture-in-Picture API（最前面フローティング窓への波形・警告の毎フレーム同期描画）
- **外部ライブラリ:** 未使用 (完全スタンドアロン構成)

### 2. AI（Gemini）の活用実績
本システムの開発にあたり、以下の設計・実装においてAIと協調（ペアプログラミング）しました。
- **音響処理・ノイズ抑制アルゴリズムの共同設計:** 話し声と打鍵音を切り分けるための「ハイパスフィルタ」「音量急上昇率（Rise-rate）」「持続信号判定」を組み合わせたトリプルノイズ抑制ゲートロジックの構築。
- **数学的判定モデルの実装:** 打鍵音の周波数特徴をベクトル化して学習し、コサイン類似度で照合する処理コードの自動生成。

## 🔒 セキュリティとプライバシーについて

GitHubをはじめとする外部へのコード公開、および利用における安全性を担保するため、本システムは以下のセキュリティ設計を採用しています。

### 1. 100% クライアントサイド処理（ローカル完結）
- マイクから取得した音声信号は、ブラウザ内の `AudioContext` （メモリ内）でのみリアルタイム解析され、処理終了後は即座に破棄されます。
- 音声データや解析ログを外部サーバーに送信・アップロードする通信処理（`fetch`, `XMLHttpRequest`, `WebSocket` 等）はソースコード内に一切存在しません。
- インターネット未接続の完全オフライン環境でも動作可能です。

### 2. キーロガー機能の完全排除（プライバシー保護）
- 「キー連動モード（keydown検知）」をONにした場合でも、JavaScriptは単に物理キーが「押されたタイミング」のイベントのみを検知し、音声解析のゲート開閉（350ms間）に使用します。
- ユーザーが「どのキーを入力したか（文字情報）」を取得・記録するコードは一切含まれておらず、キーロガーとしての動作や情報漏洩の懸念はありません。

### 3. 機密情報の排除とセキュリティ監査
- ソースコード内に API キー、アクセス認証情報、データベースパスワードなどのシークレットは一切ハードコードされていません。
- `.gitignore` にて、開発時の一時ファイルやOSが自動生成するキャッシュファイル（`.DS_Store` や `Thumbs.db` 等）の除外を設定しており、不要なローカル情報の公開を防ぎます。
- 開発者とAIによるダブルチェックによってセキュリティ静的監査を行っています。
