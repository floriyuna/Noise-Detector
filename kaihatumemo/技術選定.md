# 技術選定シート

本システムを構築するにあたり、要件である「低スペックPCでの動作」「即時の起動」「Webベース」を達成するため、各コンポーネントにおける技術選択肢を比較検討し、選定を行いました。

---

## 1. コンポーネント別 技術比較表

### ① 音響入力・フィルタ部
〇   **選択肢A: Web Audio API (`BiquadFilterNode` によるブラウザ標準フィルタリング)**
    *   **長所:** 追加のライブラリ読み込みが不要で、読み込み遅延がゼロ。ブラウザ標準で低レベルの処理が行われるため、CPU負荷が極めて低い。
    *   **短所:** 単純なハイパスフィルタやローパスフィルタなどの基本的な周波数フィルタ処理しか行えない。
*   **選択肢B: 外部ライブラリを介した WebAssembly (Wasm) カスタムDSP処理**
    *   **長所:** 複雑で急峻なカスタム遮断フィルタ（チェビシェフフィルタ等）を正確に適用できる。
    *   **短所:** ライブラリの初期ロードサイズが大きくなり起動が遅れる。低スペックPCでの動作時にCPU負荷が高くなる懸念がある。

### ② 打鍵検知・判定部
〇   **選択肢A: 時間領域での過渡特性 (アタック音) 検出アルゴリズム**
    *   **長所:** 数ミリ秒単位の非常に急峻な音量の立ち上がりを計算するだけでよいため、処理が極めて高速かつCPU負荷が最小限。
    *   **短所:** 音質（高音か低音かなど）の細かな違いを周波数情報として識別することは難しい。
*   **選択肢B: 周波数領域（FFT / 高速フーリエ変換）解析アルゴリズム**
    *   **長所:** 特定の周波数帯（例: キーボードの「カチッ」とする高音域）のみのエネルギー量を細かく監視できる。
    *   **短所:** FFT処理を行うためのバッファ時間（時間窓）により約 20〜40ms 程度の遅延が発生する。また、時間領域の処理に比べてCPU負荷が少し高い。

### ③ 自動キャリブレーション部
〇   **選択肢A: 測定期間（3秒間）の静的統計モデル算出**
    *   **長所:** ボタンが押された間の平均音量とピーク値のみを算出するため、シンプルで軽量。キーボードを打っていないことが保証された状態のノイズを確実に学習できる。
    *   **短所:** 測定後に部屋の環境音（エアコンの風量など）が変化した際、自動では追従できない（再度ボタンを押す必要がある）。
〇   **選択肢B: 動作中にしきい値を更新する動的適応モデル算出**
    *   **長所:** 時間経過とともに周囲の音が変化しても、自動的にしきい値が追従して変化する。
    *   **短所:** ユーザーがキーボードを叩き続けていると、そのキーボードの打鍵音自体を「背景ノイズ」と誤認して学習してしまい、しきい値が勝手に上昇して感度が落ちる問題（順応）が発生しやすい。
    *   **※本実装での決定: 選択肢Aと選択肢Bの両方を実装し、画面上で動作モードを切り替え可能とします。**

### ④ 警告・インターフェース部 (UI/Alert)
〇   **選択肢A: バニラ HTML5/CSS/JS ＋ Web Audio API オシレータ合成音**
    *   **長所:** 依存関係（フレームワークや警告音ファイルなど）が一切不要で、動作と表示が最も軽量。警告ビープ音の再生遅延が完全にゼロ（ミリ秒の遅れもない）。ファイルのダブルクリックだけで即時起動可能。
    *   **短所:** 警告音がシンプルな電子音（ビープ音）に制限される。画面とデータの状態の同期を自前で実装する必要がある。
*   **選択肢B: UIフレームワーク (React等) ＋ 警告音声ファイルの再生 (mp3)**
    *   **長所:** 状態管理がスマートに行え、リアルなサイレン音やカスタムの警告音を鳴らすことができる。
    *   **短所:** ビルド手順が必要になり、初期ロード時間が増える。音声ファイルの読み込みや再生開始までにブラウザのオーバーヘッドでわずかに遅延（レイテンシ）が生じる。

---

## 2. 最適な選択と選定理由

本プロジェクトでは、すべてのコンポーネントにおいて **「ブラウザ標準のWeb API（バニラ実装 ＋ Web Audio API）」** の組み合わせを選定します。

### 選定する具体的な技術仕様

| コンポーネント | 採用する技術 | 選定の理由 |
| :--- | :--- | :--- |
| **① 音響入力・フィルタ部** | **Web Audio API (`BiquadFilterNode` のハイパスフィルタ)** | 追加アセットを読み込まず、1kHz以下の低音（話し声の基音やエアコンノイズ）を低CPU負荷で確実にカットできるため。 |
| **② 打鍵検知・判定部** | **時間領域 (過渡アタック値) 検出アルゴリズム** | 時間領域の波形データを用いて、最も低負荷かつ「遅延のない状態」で急激な音量立ち上がり（キーボード強打）を検知するため。 |
| **③ 自動キャリブレーション部** | **静的モデル (3秒無音) ＆ 動的モデル (環境ノイズ自動追従) の両対応** | 環境に合わせて、手動で確実にノイズベースを決める「静的」と、エアコンの変動等に追従する「動的」を切り替えて選べるようにするため。 |
| **④ 警告・インターフェース部** | **バニラ HTML/CSS/JS ＋ Web Audioオシレータ警告音** | 外部フレームワークを使わないことで「ファイルをダブルクリックするだけ」で即時にツールが動作し、低スペックPCでの描画オーバーヘッドをゼロに抑えるため。 |

### 選定理由のまとめ
本システムのMVPおよび非機能要件である**「低スペックPCでの動作」「誰でも即座に起動できる容易性」「会話やノイズへの反応防止」**を最も高いレベルで満たすためには、ロード時間がほぼ存在せず、CPU/メモリ使用量を極限まで抑えられる「標準Web APIのみによる構築」が最適であると判断しました。
